# 11. IA: proveedores y chat

> Estado a 2026-10-21. Probado con proveedores simulados en las pruebas; no se llamó a las APIs reales durante el desarrollo.

`UnityREST.AI` habla con modelos de lenguaje usando el mismo transporte (reintentos, timeouts, HTTPS, pinning). El ensamblado se ocupa solo del consumo de las APIs; la personalidad de NPC vive en el paquete aparte `com.modernwestern.ai-npc`.

## Proveedores

| Tipo (`ChatProviderKind`) | Sirve para | Autenticación |
|---|---|---|
| `OpenAICompatible` | OpenAI, Azure OpenAI, Ollama, LM Studio, OpenRouter, Groq, Mistral, DeepSeek, vLLM y cualquier API con el formato Chat Completions | `Authorization: Bearer` |
| `Anthropic` | Claude (Messages API, `anthropic-version: 2023-06-01`) | `x-api-key` |
| `Gemini` | Google Gemini (`generateContent`) | `x-goog-api-key` |

### Presets

```csharp
ChatProviderSettings.Anthropic()                    // claude-opus-5-5, clave en ANTHROPIC_API_KEY
ChatProviderSettings.OpenAI()                       // gpt-5-mini, OPENAI_API_KEY, max_completion_tokens
ChatProviderSettings.Gemini()                       // gemini-2.5-flash, GEMINI_API_KEY
ChatProviderSettings.Ollama("llama3.2")             // http://localhost:11434/v1, sin clave
ChatProviderSettings.LmStudio("modelo")             // http://localhost:1234/v1
ChatProviderSettings.OpenRouter("openrouter/auto")  // OPENROUTER_API_KEY
ChatProviderSettings.OpenAICompatible("https://mi-proxy/v1", "modelo", "MI_VARIABLE")
```

Los modelos por defecto de OpenAI y Gemini no se verificaron contra sus APIs actuales: cámbialos si no existen.

### Campos

| Campo | Por defecto | Notas |
|---|---|---|
| `kind` | — | Formato de la API |
| `baseUrl` | Según el preset | En un juego publicado, apunta a tu backend |
| `model` | Según el preset | |
| `apiKey` | vacío | Se guarda en el asset y viaja en el build |
| `apiKeyEnvironmentVariable` | Según el preset | Se usa si `apiKey` está vacío. Útil en el editor y en escritorio |
| `maxTokens` | 16000 | Límite de salida |
| `overrideTemperature` / `temperature` | apagado / 1 | Los modelos actuales de Claude rechazan `temperature`: déjalo apagado con Anthropic |
| `effort` | vacío | `low`, `medium`, `high`... Se envía como `output_config.effort` (Anthropic) o `reasoning_effort` (OpenAI); Gemini lo ignora |
| `maxTokensParameter` | `max_tokens` | Solo OpenAI-compatible. OpenAI necesita `max_completion_tokens` en sus modelos de razonamiento |
| `timeoutSeconds` | 120 | Por intento |
| `headers` | vacío | Cabeceras extra, como las de OpenRouter |

Las peticiones de IA reintentan hasta 2 veces, con esperas de 1 a 20 s, y solo cuando el servidor rechazó la petición (429 o 503), porque son POST.

### En un asset

**Assets → Create → UnityREST → AI Chat Provider** guarda un `ChatProviderSettings` editable, con presets. `asset.CreateProvider()` devuelve el proveedor.

## Una llamada suelta

```csharp
var provider = ChatProviderSettings.Anthropic().CreateProvider();

var response = await provider.CompleteAsync(new[]
{
    ChatMessage.System("Resume en una línea."),
    ChatMessage.User(textoLargo)
});

if (response.IsSuccess) Debug.Log(response.Text);
else Debug.LogWarning($"{response.Error} {response.StatusCode}: {response.ErrorMessage}");
```

`ChatResponse` trae `Message`, `Text`, `FinishReason`, `RawFinishReason`, `Usage` (tokens de entrada y salida), `Error`, `StatusCode` y `ErrorMessage`, que es el mensaje del proveedor cuando lo hay. Como en REST, no lanza excepciones por errores de red o de la API.

### FinishReason

| Valor | Significado |
|---|---|
| `Stop` | Terminó normalmente |
| `Length` | Llegó a `maxTokens`; la respuesta está cortada |
| `ToolCalls` | Quiere ejecutar herramientas |
| `Refusal` | El modelo se negó (Claude: `stop_reason: refusal`) |
| `ContentFilter` | Bloqueado por filtros del proveedor |
| `Error`, `Other` | Fallo o motivo no estándar; mira `RawFinishReason` |

## Streaming

Pasa un callback y el texto llega a medida que se genera, por SSE:

```csharp
var response = await provider.CompleteAsync(messages, null, delta => label.text += delta, token);
```

## ChatSession: conversación con historial y herramientas

```csharp
var chat = new ChatSession(provider, "Eres un asistente conciso.");
var reply = await chat.SendAsync("¿Qué hora es en Tokio?", delta => label.text += delta, token);
```

| Miembro | Uso |
|---|---|
| `History` | Mensajes de la conversación |
| `SystemPrompt` | Se puede cambiar a mitad de la conversación; `null` lo quita |
| `Tools` | Herramientas disponibles (`List<ITool>`) |
| `MaxToolRounds` | Máximo de idas y vueltas con herramientas por mensaje (8) |
| `ApproveToolCall` | Pregunta antes de ejecutar cada herramienta; `false` la rechaza |
| `ToolExecuted` | Evento con cada herramienta ejecutada y su resultado |
| `RoundCompleted` | Evento con cada respuesta del modelo, también las que solo piden herramientas |
| `TotalUsage` | Tokens acumulados |
| `TrimHistory(n)` | Deja como máximo `n` mensajes sin cortar entre una herramienta y su resultado; devuelve lo quitado para resumirlo |
| `Clear()` | Borra la conversación y conserva el system prompt |

Si un turno falla o se cancela, se retira del historial para que se pueda reintentar. Si se alcanza `MaxToolRounds`, las llamadas pendientes reciben un resultado de error, para que el historial siga siendo válido.

### Herramientas

```csharp
chat.Tools.Add(Tool.Create(
    "get_weather",
    "Clima actual de una ciudad.",
    new ToolSchema()
        .String("city", "Nombre de la ciudad")
        .Enum("unit", "Unidad", false, "celsius", "fahrenheit"),
    args => JsonConvert.SerializeObject(Weather.For((string)args["city"]))));

// Asíncrona y con cancelación:
chat.Tools.Add(Tool.Create("search_inventory", "Busca un objeto.", new ToolSchema().String("query", "Texto"),
    async (args, ct) => await inventory.SearchAsync((string)args["query"], ct)));
```

- Las herramientas que pide el modelo en un mismo turno se ejecutan en paralelo.
- Si una lanza una excepción, el modelo recibe el mensaje como error y puede corregirse.
- `ToolSchema` arma el JSON Schema: `String`, `Number`, `Integer`, `Boolean`, `Enum`, `Array` y `Object` (anidado). También acepta un `JObject` propio.
- Los nombres deben cumplir `^[a-zA-Z0-9_-]{1,64}$` (regla de los proveedores).
- Con Anthropic y streaming, las herramientas se envían con `eager_input_streaming`. Algunos proxys rechazan ese campo.

### Imágenes

```csharp
var screenshot = ScreenCapture.CaptureScreenshotAsTexture();
await chat.SendAsync(ChatMessage.User("¿Qué ves?", ChatImage.FromTexture(screenshot)));
Destroy(screenshot);
```

También `ChatImage.FromPng(bytes)`, `FromJpg(bytes)` o `new ChatImage(mediaType, base64)`. El modelo debe aceptar imágenes.

### Razonamiento conservado

Claude devuelve bloques `thinking` firmados y Gemini, `thoughtSignature`. Cuando la conversación sigue con el mismo proveedor, esas respuestas se reenvían tal cual, como exigen las APIs para usar herramientas en varios turnos. Si cambias `chat.Provider` a otro proveedor, se reenvían en formato neutro.

## Seguridad y costos

- No publiques un juego con tu clave de API: cualquiera puede extraerla y gastar en tu cuenta. Usa un backend propio como proxy y apunta `baseUrl` a él.
- `maxTokens` limita el costo por respuesta. `ChatSession.TotalUsage` acumula los tokens usados.
- En WebGL, Anthropic exige además la cabecera `anthropic-dangerous-direct-browser-access`, que el paquete agrega. Aun así, la recomendación del proxy sigue en pie.
